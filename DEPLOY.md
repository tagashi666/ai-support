# Развёртывание ai-support

Порядок такой: сервер → бот → запуск → nginx → каналы → AI. Каждый шаг
проверяемый, включать всё сразу не нужно и не стоит.

---

## 1. Что нужно на сервере

- Ubuntu 22.04+ или Debian 12+
- Docker 24+ и `docker compose` v2
- 512 МБ свободной памяти, 2 ГБ диска под базу и вложения
- `openssl` (генерация токена панели)

```bash
docker --version && docker compose version && openssl version
```

Внешние соединения нужны к `api.telegram.org`, к вашему боту бедолаги и к
эндпоинту AI. Входящих портов не требуется вообще: бот работает на long polling,
а панель наружу отдаёт nginx.

---

## 2. Бот

**@BotFather → Bot Settings → Business Mode → Enable.**

Без этого флага подключение к аккаунту отвалится с `BOT_BUSINESS_MISSING`.
`selfcheck` проверяет флаг и не даст запуститься вслепую.

Токен из BotFather понадобится на следующем шаге. Отдельный бот заводить не
обязательно, но лучше отдельный: к аккаунту можно подключить только один
бизнес-бот, и смешивать его с боевым ботом продаж не стоит.

---

## 3. Первый запуск

```bash
tar xzf ai-support.tar -C /root --strip-components=1 --one-top-level=ai-support
cd /root/ai-support
./install.sh
```

Архив gzip'нутый, даже если скачался без расширения `.gz` — `tar` определит
сжатие сам.

Первый прогон создаёт `.env`, генерирует токен панели и **останавливается**.
Токен печатается в консоль — сохраните его, входить в панель будете им.

Заполните в `.env` как минимум:

```ini
BOT_TOKEN=7712345678:AA...        # из BotFather
AI_MODE=off                       # AI включим позже, отдельным шагом
BEDOLAGA_ENABLED=false            # бедолагу тоже позже
```

Запустите второй раз:

```bash
./install.sh
```

Он соберёт образ, прогонит предполётную проверку и поднимет контейнер.
Если проверка не прошла — контейнер не стартует, это намеренно.

```bash
docker compose logs -f
```

Ожидаемое в логах: применённые миграции, «Отправитель канала tg_dm
зарегистрирован», «Панель слушает», и предупреждение об отсутствии
бизнес-подключения — оно исчезнет на следующем шаге.

---

## 4. Подключение аккаунта поддержки

В аккаунте, на который сейчас пишут клиенты:

**Настройки → Telegram для бизнеса → Чат-боты** → выбрать своего бота.

Права выдайте **только два**:

- отвечать на сообщения;
- отмечать сообщения прочитанными.

Управление профилем, подарками, звёздами и историями боту не нужно —
не выдавайте того, чем он не пользуется.

В разделе **«Чаты»** начните с белого списка из одного-двух своих аккаунтов.
Напишите с них в поддержку: диалог должен появиться в панели за секунду.
Убедились — расширяйте на всех.

Premium для подключённых ботов не требуется.

> **История не подтянется.** Bot API не умеет читать переписку задним числом.
> Панель начнёт с чистого листа, старые диалоги останутся в самом Telegram.

## 5. Панель наружу — реверс-прокси

Панель слушает `127.0.0.1:8080` — публиковать её напрямую нельзя.
Docker пишет правила в обход UFW, поэтому `ports: "8080:8080"` открыл бы её
всему интернету, даже при закрытом фаерволе. Наружу её отдаёт nginx: терминирует
TLS, пробрасывает WebSocket и добавляет `X-Forwarded-For`, по которому панель
отличает адрес оператора от локального (нужно для блокировки перебора токена).

Готовый конфиг — в `deploy/ai-support.conf`.

**5.1. Домен.** Заведите A-запись (и AAAA, если есть IPv6) на IP сервера,
например `support.вашдомен.ru`. Дальше в командах — этот домен.

**5.2. Установите nginx и certbot.**

```bash
apt update && apt install -y nginx certbot python3-certbot-nginx
```

**5.3. Поставьте конфиг** (перед выпуском сертификата — он работает по 80 порту):

```bash
cp deploy/ai-support.conf /etc/nginx/sites-available/ai-support.conf
# подставьте свой домен вместо support.example.com
sed -i 's/support\.example\.com/support.вашдомен.ru/g' /etc/nginx/sites-available/ai-support.conf
ln -s /etc/nginx/sites-available/ai-support.conf /etc/nginx/sites-enabled/
rm -f /etc/nginx/sites-enabled/default   # чтобы дефолтный сайт не перехватывал
```

**5.4. Выпустите сертификат.** До первого выпуска путей к сертификату ещё нет,
поэтому проверяйте только 80-й блок и выпускайте через nginx-плагин — он сам
допишет пути и перезагрузит nginx:

```bash
certbot --nginx -d support.вашдомен.ru
nginx -t && systemctl reload nginx
```

Продление автоматическое (таймер `certbot.timer`); 80-й блок в конфиге держит
для этого ACME-проверку открытой.

**5.5. Откройте порты фаервола** (Docker в обход UFW открывает только свои
проброшенные порты, 80/443 нужно разрешить явно):

```bash
ufw allow 80,443/tcp
```

Проверьте: `https://support.вашдомен.ru` должен показать вход в панель, а после
входа диалоги — обновляться вживую (это и есть работающий WebSocket).

Критично: блок `proxy_set_header Upgrade` и длинные таймауты в конфиге — без них
WebSocket рвётся, и панель перестаёт обновляться вживую.

Для WebSocket и вложений панель выдаёт отдельный билет на чтение сроком на
десять минут. Основной токен в URL не попадает. Билет может осесть в access-логе,
поэтому в конфиге лог панели выключен (`access_log off;`), а сам лог стоит
считать чувствительным.

Разумно добавить ещё один рубеж — ограничение по IP или basic auth поверх токена.

> **Другой прокси.** Caddy/Traefik тоже подойдут — важны три вещи: TLS,
> апгрейд WebSocket на `/ws` и заголовок `X-Forwarded-For` от локального прокси
> (панель доверяет ему только с loopback).

## 6. Канал бедолаги

В `.env`:

```ini
BEDOLAGA_ENABLED=true
BEDOLAGA_API_URL=https://bot.example.com/api
BEDOLAGA_API_TOKEN=...
BEDOLAGA_POLL_SECONDS=60
```

Токен — ключ webapi бота, он уходит в заголовке `X-API-Key`. Проверьте до
перезапуска:

```bash
docker compose run --rm ai-support node dist/cli/selfcheck.js
docker compose up -d
```

Первая синхронизация затянет активные тикеты целиком. Вся их переписка
помечается как история: AI на неё не реагирует и SLA-уведомлений не шлёт.

Знайте про два ограничения канала:

- **Ответ в тикет — только текст.** `POST /tickets/{id}/reply` принимает
  `message_text`; картинку в тикет отправить нельзя. Входящие вложения
  скачиваются и показываются в панели.
- **Эндпоинт не идемпотентен**: сообщение коммитится до ответа. Ретраи на нём
  отключены намеренно. Если отправка упала по таймауту — откройте тикет и
  посмотрите, дошёл ли ответ, прежде чем повторять.

## 7. Карточка клиента

Необязательный шаг. Подключает ваш Support API, чтобы оператор видел подписку
и платежи рядом с диалогом:

```ini
SUPPORT_API_ENABLED=true
SUPPORT_API_URL=https://api.example.com
SUPPORT_API_TOKEN=...
SUPPORT_API_USER_PATH=/api/support/user_info
```

Ожидается `POST` с телом `{"telegram_id": 123}`. Ответ показывается в панели
как есть, поэтому подойдёт любая форма. Если API недоступен, карточка просто
не заполнится — на работу поддержки это не влияет.

Когда бедолага включена, она тоже отдаёт данные клиента, и оба источника
объединяются в одну карточку.

## 8. AI — только после всего остального

```ini
AI_MODE=suggest
AI_BASE_URL=https://api.moonshot.ai/v1
AI_API_KEY=...
AI_MODEL=kimi-k2-0905-preview
AI_BRAND=Поддержка
```

Какого провайдера выбрать, сколько это стоит и готовые конфиги под каждый —
в **[PROVIDERS.md](PROVIDERS.md)**. Коротко: при 30 обращениях в день счёт
выходит меньше доллара в месяц, поэтому гнаться за бесплатным тарифом стоит
только на обкатке.

**Начинайте с `suggest`.** В этом режиме модель пишет черновик, а отправляет
человек. Ничего не уходит клиенту без вашей кнопки.

База знаний собирается из двух источников и обновляется каждые 15 минут:

- `kb/*.md` в каталоге проекта (панель может редактировать эти файлы);
- FAQ из админки бедолаги.

Правьте `kb/*.md` прямо на сервере — перезапуск не нужен, следующая
синхронизация подхватит.

### Когда переключать на `auto`

Смотрите раздел «графики» в панели: доля принятых предложек против отклонённых.
Пока отклоняете заметную часть — рано. Переключать можно точечно, на отдельном
диалоге, не трогая глобальный режим.

Даже в `auto` ответ уйдёт человеку, если модель просит помощи, уверенность ниже
порога, тема чувствительная (возвраты, двойные списания, обвинения, угрозы
судом, прямая просьба позвать оператора), диалог эскалирован, человек отвечал в
нём последние 30 минут или исчерпан лимит автоответов в час.

## 9. Уведомления о просрочке

```ini
ALERT_CHAT_ID=-1001234567890
SLA_FIRST_RESPONSE_MINUTES=30
```

Бот должен состоять в этом чате или канале. Уведомление приходит один раз на
диалог, не чаще пяти за цикл проверки, и только по диалогам свежее суток —
иначе первая же синхронизация архива прислала бы сотню сообщений.

## Эксплуатация

```bash
docker compose logs -f              # логи
docker compose restart              # перезапуск
docker compose run --rm ai-support node dist/cli/selfcheck.js   # диагностика
curl -H "Authorization: Bearer $TOKEN" http://127.0.0.1:8080/api/health
```

### Обновление

```bash
cd /root/ai-support
docker compose down
tar xf ~/ai-support.tar --strip-components=1
./install.sh
```

Установщик сверяется с `MANIFEST` и удаляет файлы, которых в новой версии
больше нет. Без этого распаковка поверх оставляет модули от прошлых раскладок,
и сборка падает на конфликте типов — `.env`, `data/` и `kb/` при этом не
затрагиваются.

`.env` и `data/` не перезаписываются. Если в новой версии появились настройки,
которых нет в вашем `.env`, установщик допишет их из шаблона со значениями по
умолчанию, покажет список и остановится — чтобы вы посмотрели, что добавилось,
а не получили новое поведение молча.

Миграции базы применяются на старте автоматически и повторно не проигрываются.

### Резервная копия

Всё состояние — в `data/`. База в режиме WAL, поэтому копировать нужно вместе
со спутниками либо через `.backup`:

```bash
docker compose exec ai-support node -e \
  "new (require('better-sqlite3'))('/app/data/ai-support.db').backup('/app/data/backup.db')"
tar czf ai-support-$(date +%F).tar.gz data/backup.db kb .env
```

`.env` содержит токены — храните копию соответственно.

## Если что-то не работает

**Диалоги не появляются.** Проверьте, что Business Mode включён в BotFather и
бот подключён в настройках аккаунта. В логах при старте должно быть «Активное
бизнес-подключение». Если чат попал в исключения списка «Чаты», сообщения из
него бот не увидит.

**Ответ не уходит, панель пишет про окно.** Telegram разрешает боту писать в
личный чат, только если оттуда было входящее за последние 24 часа. Это
ограничение платформы, обойти его нельзя — отвечайте с телефона вручную.

**Ответ не уходит, ошибка от Telegram.** Скорее всего не выдано право
«отвечать на сообщения». Перевыдайте права в настройках аккаунта.

**Сборка падает на конфликте типов после обновления.** На сервере остались
файлы от прошлой раскладки модулей. Лечится начисто:

```bash
cd ~/ai-support && rm -rf src scripts public deploy
tar xf ~/ai-support.tar --strip-components=1 && ./install.sh
```

**База не пишется, ошибка доступа.** Каталог `data/` принадлежит root, а
контейнер работает под uid 1000:

```bash
chown -R 1000:1000 data && docker compose restart
```

**Панель открывается, но не обновляется вживую.** Не проброшен WebSocket —
проверьте заголовки `Upgrade`/`Connection` в конфиге nginx.

**Вложения не показываются.** Они скачиваются фоном раз в 15 секунд.
Ссылки Telegram живут около часа, после пяти неудачных попыток вложение
бросается — в панели останется пометка о типе файла.

**AI отвечает через раз, в логах 429.** Упёрлись в лимит бесплатного тарифа.
Клиент ждёт по `Retry-After` и повторяет до трёх раз, но если лимит суточный —
поможет только смена провайдера, см. PROVIDERS.md.

**AI молчит.** Проверьте `AI_MODE`, ключ и что база знаний не пуста
(`selfcheck` покажет число документов). Модель не отвечает на сообщения
старше `AI_MAX_AGE_MINUTES` и на вложения без текста.

**Тикеты бедолаги не приходят.** `selfcheck` покажет, отвечает ли API и
сколько активных тикетов видно. Опрашиваются статусы `open` и `pending`.
