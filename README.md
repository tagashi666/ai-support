**AI Support** — единый центр поддержки для Telegram Business, Telegram-ботов
и тикетов Bedolaga. Панель объединяет переписки, операторов, шаблоны, базу
знаний, SLA, статистику, серверы Remnawave и безопасного AI-помощника.

Текущая стабильная версия — **2.0.1**. Заметки о выпуске находятся в
[CHANGELOG.md](CHANGELOG.md), готовые сборки — в разделе
[Releases](https://github.com/tagashi666/ai-support/releases).

## Главное в версии 2.0

- **Автономный запуск.** Для первого старта достаточно токена панели.
  Telegram, Bedolaga, Remnawave и AI подключаются позже и не блокируют работу
  интерфейса.
- **Единый inbox.** Telegram Business, личные сообщения нескольким ботам и
  тикеты Bedolaga отображаются в одной очереди.
- **Несколько источников.** Одновременно поддерживаются несколько ботов,
  Business-аккаунтов и панелей Remnawave.
- **Папки источников.** Один источник можно включить сразу в несколько папок,
  как в Telegram. Поиск и фильтры работают внутри выбранной папки.
- **Живые диалоги.** Новые сообщения и карточки приходят через WebSocket;
  резервная синхронизация раз в пять секунд восстанавливает пропущенное событие.
- **Telegram-профили.** В личных сообщениях показываются имя, username и
  аватар клиента. Для Bedolaga используется безопасная буквенная заглушка.
- **Синхронизация Bedolaga.** Ответы, фото и статусы привязаны к исходному
  тикету. Закрытие диалога в панели закрывает тикет во внешней системе, а
  внешнее закрытие возвращается в панель.
- **Полноценное обновление по кнопке.** Отдельный ограниченный host-updater
  скачивает точный GitHub Release, проверяет его, делает backup, выполняет
  health-check и автоматически откатывается при ошибке.
- **Командная работа.** Есть роли, отдельные отзываемые токены, назначения,
  присутствие операторов в диалоге и журнал аудита.
- **Мультимодальный AI.** Помощник понимает текст и изображения, использует
  базу знаний, карточку текущего клиента и безопасный слепок состояния узлов.
- **Корректная аналитика.** Метрики считаются по реальным событиям выбранного
  периода; статистический период можно сбросить без удаления переписки.

## Быстрый старт

### Требования

- Linux-сервер;
- Docker Engine;
- Docker Compose v2;
- `openssl`;
- root-доступ рекомендуется для автоматической установки host-updater.

### Установка

```bash
git clone https://github.com/tagashi666/ai-support.git
cd ai-support
./install.sh
```

Установщик:

1. создаст `.env` из безопасного шаблона;
2. сгенерирует случайный `PANEL_TOKEN`;
3. выставит для `.env` права `0600`;
4. соберёт контейнер и выполнит self-check;
5. запустит панель на `127.0.0.1:8080`;
6. при запуске от root установит ограниченные обработчики обновлений и
   добавления источников.

Токен показывается один раз и сохраняется в `.env`. После запуска откройте
`http://127.0.0.1:8080`, введите токен и завершите настройку в интерфейсе.

Если в новой версии появились переменные окружения, `install.sh` сначала
добавит отсутствующие ключи в `.env` и остановится. Проверьте новые значения и
запустите установщик повторно.

### Голый режим

Пустые токены интеграций допустимы. Минимальная установка предоставляет:

- панель и локальное хранилище;
- пользователей и роли;
- шаблоны ответов;
- редактор базы знаний;
- настройки, диагностику и журнал аудита.

Каналы можно добавить позже. Отключённая интеграция не должна мешать запуску
остальной системы.

## Каналы и источники

| Источник | Что поддерживается |
| --- | --- |
| Telegram Business | Входящие и ручные исходящие, имя, username, аватар, медиа |
| Telegram-бот | Личные сообщения, несколько ботов, медиа и профиль клиента |
| Bedolaga | Тикеты, ответы, фото, приоритет и двусторонние статусы |
| Remnawave | Несколько панелей, профиль подписки и состояние узлов |

Новые Telegram-источники и панели Remnawave добавляются в разделе настроек.
Секрет из формы не сохраняется в браузере и не возвращается через API: панель
создаёт приватное задание, а ограниченный root-only обработчик применяет его на
хосте, проверяет здоровье приложения и при неудаче восстанавливает `.env`.

Если установщик запускался не от root, один раз установите обработчики вручную:

```bash
sudo bash scripts/install-host-updater.sh "$(pwd)"
```

Для каждой панели Remnawave можно отдельно задать:

- отображаемое название сервиса;
- приветственную фразу;
- текст передачи оператору;
- псевдонимы узлов;
- режим только для чтения.

Один источник разрешено включать в несколько папок. Изменение или удаление
папки не удаляет источник и не затрагивает историю сообщений.

Подробная настройка каналов описана в [DEPLOY.md](DEPLOY.md).

## Статусы диалогов

Базовая логика едина для всех каналов:

- новое сообщение клиента переводит диалог в статус **«Открыт»**;
- ответ оператора переводит его в **«Ждём клиента»**;
- отсутствие активности в течение 24 часов переводит диалог в **«Решён»**;
- новое входящее сообщение повторно открывает решённый диалог.

Для Bedolaga смена статуса сначала подтверждается внешним API. Если внешний
запрос не прошёл, локальная карточка не притворяется закрытой. Фоновая
синхронизация также подхватывает тикеты, закрытые непосредственно в Bedolaga.

## AI-помощник

AI по умолчанию выключен. Доступны три режима:

- `off` — AI не вызывается;
- `suggest` — готовит черновик, отправляет оператор;
- `auto` — отправляет только ответы, прошедшие все защитные проверки.

Штатная конфигурация Groq для 2.0:

- основная мультимодальная модель — `qwen/qwen3.8-27b`;
- текстовая резервная модель — `openai/gpt-oss-120b`;
- изображения никогда не отправляются в модель, не заявленную в
  `AI_VISION_MODELS`.

Минимальная настройка:

```dotenv
AI_MODE=suggest
AI_BASE_URL=https://api.groq.com/openai/v1
AI_API_KEY=<КЛЮЧ_ПРОВАЙДЕРА>
AI_MODEL=qwen/qwen3.8-27b
AI_MODEL_FALLBACK=openai/gpt-oss-120b
AI_VISION_MODELS=qwen/qwen3.8-27b
```

После изменения `.env` перезапустите приложение через `./install.sh` либо
Docker Compose. Начинать эксплуатацию рекомендуется в режиме `suggest`.

### Защита от ответа поверх оператора

Открытие карточки само по себе не выключает AI. Пауза включается, когда
оператор:

- начал печатать;
- явно взял диалог;
- отправил ответ;
- передал разговор человеку.

Состояние проверяется до вызова модели, после генерации и непосредственно перед
отправкой. Поэтому устаревший ответ AI не должен уйти поверх уже начавшего
работу оператора.

### На чём строится ответ

Модель получает только ограниченный контекст текущего обращения:

- последние сообщения этого диалога;
- релевантные статьи локальной базы знаний;
- очищенную карточку текущего клиента;
- при включённой интеграции — свежий очищенный слепок состояния узлов;
- локально загруженные изображения текущего сообщения.

У модели нет инструментов управления Telegram, Bedolaga, Remnawave, Docker,
файлами или настройками. Единственное допустимое действие AI — предложить текст
ответа в текущий диалог.

Автоматическая отправка дополнительно требует опоры на разрешённые источники,
достаточной уверенности и отсутствия чувствительной темы. Исходящий фильтр
блокирует секреты, ключи, внутренние адреса и подписочные ссылки.

Подробнее: [PROVIDERS.md](PROVIDERS.md) и [SECURITY.md](SECURITY.md).

## База знаний и обучение

Статьи хранятся в `kb/*.md` и редактируются из панели. FAQ Bedolaga может
синхронизироваться как дополнительный источник.

AI не меняет опубликованную базу самостоятельно. После завершённых диалогов он
может подготовить черновики вопрос–ответ. Руководитель проверяет, редактирует и
публикует их вручную.

Ручной запуск майнинга:

```bash
npm run kb:mine -- --archive --status resolved --limit 300
```

Черновики находятся в `data/kb-draft/` и не попадают в индекс до публикации.

## Команда и доступ

Владелец создаёт пользователей в разделе **«Команда»**. Поддерживаются роли:

- администратор;
- руководитель;
- оператор;
- наблюдатель.

Каждый сотрудник получает отдельный токен. Его можно отозвать без замены
`PANEL_TOKEN`. Основной токен остаётся аварийным административным доступом.

Панель показывает, кто сейчас смотрит диалог, позволяет назначить
ответственного, взять или освободить обращение. Изменения доступа и важные
действия записываются в журнал аудита без секретных значений.

## SLA и статистика

Политики SLA задают отдельные сроки первого ответа и решения для каждого
приоритета. Рабочая очередь показывает приближающиеся и уже нарушенные сроки.

Статистика включает:

- входящие сообщения и новые диалоги;
- медиану и p90 первого ответа оператора;
- решённые обращения;
- медиану и среднее время решения;
- долю ответов AI и оператора;
- текущую очередь без ответа;
- объём базы знаний.

Исторический импорт не должен становиться новым событием периода. Сброс
статистики создаёт новую точку отсчёта и не удаляет диалоги, сообщения или
аудит.

## Обновление по кнопке

В production рекомендуется выбрать канал `stable`:

```dotenv
UPDATE_ENABLED=true
UPDATE_CHANNEL=stable
UPDATE_REPOSITORY=tagashi666/ai-support
```

Панель только проверяет GitHub Releases и записывает приватный запрос в
`data/`. Она не получает Docker socket и не управляет systemd. Отдельный
host-updater:

1. принимает только допустимый тег версии;
2. скачивает опубликованный архив и SHA-256;
3. проверяет состав архива и контрольную сумму;
4. создаёт резервную копию приложения и согласованную копию SQLite;
5. устанавливает новую версию и собирает контейнер;
6. проверяет приложение, базу и, если настроено, nginx;
7. автоматически восстанавливает backup при любой ошибке.

В интерфейсе отображаются живой этап, прогресс, путь резервной копии и
доступность отката. Обычная кнопка появляется только для более новой версии;
переустановка текущего релиза вынесена в отдельный аварийный раздел.

Привилегированный host-updater намеренно не заменяет сам себя кодом из
скачанного релиза. Если выпуск меняет его реализацию, администратор один раз
обновляет ограниченный исполнитель из уже проверенной локальной копии:

```bash
sudo ./scripts/install-host-updater.sh /root/ai-support
```

## Развёртывание

Контейнер публикует панель только на loopback-интерфейсе:

```text
127.0.0.1:8080
```

Для внешнего доступа используйте reverse proxy с HTTPS. Пример nginx находится
в [deploy/ai-support.conf](deploy/ai-support.conf), полная инструкция — в
[DEPLOY.md](DEPLOY.md).

Основные команды:

```bash
docker compose ps
docker compose logs -f ai-support
docker compose up -d --build
docker compose run --rm ai-support node dist/cli/selfcheck.js
```

Не публикуйте порт контейнера на `0.0.0.0` и не передавайте веб-контейнеру
`/var/run/docker.sock`.

## Проверки для разработки

```bash
npm ci
npm run typecheck
npm run build
npm test
npm run release:check
```

`npm test` проверяет хранилище, каналы, AI-предохранители, Bedolaga, роли,
WebSocket, интерфейс и безопасность. `npm run release:check` собирает архив по
явному allowlist и отказывает, если в него попали `.env`, `data/`, `.git`,
зависимости или служебные каталоги.

## Хранение данных и приватность

- рабочие секреты находятся только в `.env` с правами `0600`;
- `.env`, SQLite, медиа, черновики, резервные копии и runtime-файлы исключены
  из Git;
- релизный архив собирается по явному списку разрешённых файлов;
- токен панели не передаётся в query string;
- вложения и WebSocket используют короткоживущие билеты только для чтения;
- секреты в интерфейсе маскируются и не возвращаются через API;
- аудит очищает поля, похожие на токены и персональные данные.

Не добавляйте реальные токены, домены конкретной установки, экспорт переписки,
дампы базы, пользовательские медиа или резервные копии в issue и pull request.

## Ограничения

- панель предназначена для самостоятельного размещения на доверенном сервере;
- SQLite не зашифрована на диске — доступ к серверу означает доступ к данным;
- текст обращений и разрешённые изображения передаются выбранному AI-провайдеру;
- исходящие Telegram Business ограничены 24-часовым окном платформы;
- Bedolaga и Remnawave зависят от совместимости их внешних API;
- разрушающие действия Remnawave рекомендуется держать выключенными через
  `REMNAWAVE_READONLY=true`.
