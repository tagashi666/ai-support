# ai-support

[![CI](https://github.com/tagashi666/ai-support/actions/workflows/ci.yml/badge.svg)](https://github.com/tagashi666/ai-support/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)
[![Node.js 22+](https://img.shields.io/badge/Node.js-22%2B-43853d.svg)](package.json)

Самостоятельно размещаемая панель поддержки для Telegram. Личные сообщения
аккаунта техподдержки и тикеты внешней системы попадают в единый инбокс, а AI
готовит ответы с опорой на базу знаний.

Личные сообщения подключаются через официальный механизм Telegram Business —
connected business bot. MTProto и файл сессии не используются: бот получает
`business_message` и отвечает от имени подключённого аккаунта.

## Возможности

- **Два канала в одном инбоксе:** Telegram Business и тикеты внешней системы.
- **Ответ от имени аккаунта:** оператор работает из панели, не переключаясь
  между чатами и админками.
- **Три режима AI:** выключен, предлагает черновик или отвечает автоматически.
- **Безопасный автоответ:** чувствительные темы, недостаточная уверенность и
  недавняя работа оператора автоматически возвращают диалог человеку.
- **Контекст клиента:** карточка из Support API и интеграции тикетов.
- **Контроль окна Telegram:** панель отслеживает разрешённые 24 часа для ответа.
- **Передача оператору:** AI предупреждает клиента и замолкает до ответа человека.
- **Уведомления:** новые обращения, ответы AI, эскалации, агрессия, передача
  человеку и просрочки приходят в Telegram.
- **Рабочие инструменты:** шаблоны, внутренние заметки, статистика и вложения.
- **База знаний:** Markdown, внешний FAQ, полнотекстовый поиск и майнинг
  проверенных ответов из переписки.

## Быстрый старт

### Docker

Понадобятся Docker, Docker Compose v2, домен для панели и Telegram-бот с
включённым Business Mode.

```bash
git clone https://github.com/tagashi666/ai-support.git
cd ai-support

./install.sh          # создаст .env и сгенерирует токен панели
nano .env             # укажите BOT_TOKEN, остальные интеграции можно включить позже
./install.sh          # проверит конфигурацию, соберёт образ и запустит сервис
```

По умолчанию панель доступна только локально: `http://127.0.0.1:8080`. При
первом открытии она запросит токен из `PANEL_TOKEN`.

### Без Docker

Требуется Node.js 22 или новее.

```bash
cp .env.example .env
nano .env
npm ci
npm run selfcheck
npm run dev
```

Полная установка с nginx, TLS и диагностикой описана в [DEPLOY.md](DEPLOY.md).

## Подключение каналов

### Telegram Business

1. В **@BotFather → Bot Settings → Business Mode** включите Business Mode.
2. В аккаунте поддержки откройте **Настройки → Telegram для бизнеса → Чат-боты**
   и выберите бота.
3. Выдайте только два права: **отвечать на сообщения** и **отмечать прочитанным**.
4. Сначала ограничьте список чатов своими тестовыми аккаунтами. После проверки
   расширьте доступ на клиентов.

`npm run selfcheck` проверяет Business Mode и сообщает `BOT_BUSINESS_MISSING`,
если он выключен. Premium не требуется, но к одному аккаунту можно подключить
только одного бизнес-бота.

### Внешняя система тикетов

Второй канал включается переменными `BEDOLAGA_*`. Поллер импортирует активные
тикеты и их историю, а ответы отправляет через API внешней системы. Порядок
настройки и ограничения этого канала приведены в [DEPLOY.md](DEPLOY.md).

## AI и безопасность ответов

### Режимы

| `AI_MODE` | Поведение |
|---|---|
| `off` | AI не обрабатывает диалоги |
| `suggest` | AI пишет черновик, отправляет оператор — рекомендуемый стартовый режим |
| `auto` | AI отправляет ответ самостоятельно, если его пропустили ворота |

Режим можно переопределить для отдельного диалога: явные `suggest` и `auto`
сильнее глобального режима по умолчанию. Глобальный `off` остаётся аварийным
рубильником и отключает AI во всех диалогах.

Даже в режиме `auto` ответ остаётся оператору, если:

- модель запросила человека или уверенность ниже `AI_MIN_CONFIDENCE`;
- вопрос касается возврата, двойного списания, суда или прямой просьбы об операторе;
- диалог эскалирован;
- оператор недавно отвечал в этом диалоге;
- исчерпан лимит `AI_AUTO_PER_HOUR`;
- ответ не подтверждён разрешённым источником знаний.

Каждый черновик сохраняется в `ai_suggestion`. Соотношение отправленных,
отредактированных и отклонённых предложений видно в статистике и помогает
оценить готовность к режиму `auto`.

Подробная модель угроз, границы возможностей AI и защита панели описаны в
[SECURITY.md](SECURITY.md).

### Окно ответа Telegram

Telegram разрешает бизнес-боту отвечать в личный чат только в течение 24 часов
после последнего входящего сообщения. Обойти это ограничение нельзя.

- время последнего входящего хранится в `conversation.last_inbound_at`;
- `Outbox` блокирует отправку после закрытия окна;
- AI возвращает `skip`, не вызывая Telegram;
- композер панели предупреждает об истечении времени и затем блокируется.

Для тикетов внешней системы это окно не применяется.

## База знаний

### Источники

База синхронизируется каждые 15 минут из двух источников:

- `kb/*.md` — первый заголовок Markdown становится названием статьи;
- внешний FAQ — если включена интеграция тикетов.

Поиск работает через FTS5 в SQLite, без отдельной векторной базы и сервиса
эмбеддингов. Удалённые из источника документы исчезают и из индекса.

### Майнинг из переписки

Поддерживаются три источника:

```bash
# закрытые тикеты внешней системы
npm run kb:mine -- --archive --dry-run
npm run kb:mine -- --archive --limit 300

# экспорт Telegram Desktop в формате JSON
npm run kb:mine -- --export ~/result.json
npm run kb:mine -- --export ~/result.json --me user123456789

# накопленные панелью диалоги
npm run kb:mine          # диалоги, где предложенный ответ исправили или отклонили
npm run kb:mine -- --all # все отвеченные диалоги
```

Bot API не отдаёт прошлую историю личных чатов, поэтому для неё требуется
экспорт Telegram Desktop. Перед отправкой материала модели система удаляет
ключи, ссылки подписок, UUID, токены, карты, телефоны, IP-адреса, Telegram ID и
имена пользователей. Пары с остаточными признаками секрета отбрасываются.

Схожие обращения сначала группируются по темам, затем каждая тема превращается
в статью. Запросы режутся по токенам и учитывают лимиты провайдера. `--dry-run`
показывает темы, расход и ожидаемое время, но не запускает синтез.

Результаты сохраняются в `kb/draft/` и не участвуют в ответах до ручной проверки:

```bash
mv kb/draft/statya.md kb/
```

## Развёртывание

### Обновление контейнера

```bash
docker compose up -d --build
```

Порт `8080` публикуется только на `127.0.0.1`: открытый `8080:8080` обошёл бы
правила UFW. Внешний HTTPS-доступ должен предоставлять реверс-прокси.

### nginx и TLS

Готовый конфиг находится в [`deploy/ai-support.conf`](deploy/ai-support.conf).
Он завершает TLS, передаёт WebSocket и корректный `X-Forwarded-For`.

```bash
apt install -y nginx certbot python3-certbot-nginx

cp deploy/ai-support.conf /etc/nginx/sites-available/ai-support.conf
sed -i 's/support\.example\.com/support.вашдомен.ru/g' \
  /etc/nginx/sites-available/ai-support.conf
ln -s /etc/nginx/sites-available/ai-support.conf /etc/nginx/sites-enabled/
rm -f /etc/nginx/sites-enabled/default

certbot --nginx -d support.вашдомен.ru
nginx -t && systemctl reload nginx
ufw allow 80,443/tcp
```

После настройки укажите `PANEL_URL=https://support.вашдомен.ru`, чтобы ссылки
из уведомлений открывали нужный диалог. DNS, автоматическое продление
сертификата и вариант с Caddy разобраны в [DEPLOY.md](DEPLOY.md).

## Проверка и диагностика

### Проверки проекта

```bash
npm run typecheck  # проверка типов
npm test           # тесты без сети и настоящих токенов
npm run selfcheck  # проверка конфигурации текущего сервера
```

| Набор | Что проверяет |
|---|---|
| `uitest.ts` | структура и инварианты интерфейса |
| `smoke.ts` | Telegram Business, дедупликация, окно ответа и Outbox |
| `webtest.ts` | API панели, авторизация и WebSocket |
| `aitest.ts` | AI-ворота, модель, FTS, поллер и регрессии |
| `minetest.ts` | экспорт Telegram, архив тикетов и группировка тем |
| `notifytest.ts` | уведомления, ограничения частоты и ошибки доставки |
| `sectest.ts` | фильтр исходящего, билеты, лимиты и read-only операции |

### Клиент не находится в Remnawave

```bash
docker compose run --rm ai-support node dist/cli/rwprobe.js 123456789 example_user
```

Команда показывает ответы точечных методов, построение индекса и найденные
совпадения. Та же диагностика доступна в панели по кнопке «Почему не нашёлся».

Поиск учитывает `telegramId`, служебное имя `user_{telegram_id}_*`, Telegram ID
и `@username` в описании, а также short UUID ссылки подписки. Поскольку параметр
`search` некоторых версий панели ненадёжен, индекс загружается постранично и
проверяется локально.

### Ошибки прав доступа

Если панель не может сохранить статью или базу:

```bash
chown -R 1000:1000 kb data
docker compose restart
```

Контейнер работает под UID `1000`. `install.sh` выставляет владельца каталогов,
а `npm run selfcheck` проверяет возможность записи до запуска.

## Архитектура

```text
business_message ──┐                        ┌── business_connection_id
                   ├──→ Store ──→ Outbox ───┤
external tickets ──┘      │                 └── API ответа в тикет
                          ↓
                   панель (WS) + AI + SLA
```

`Outbox` — единственная точка исходящей отправки. Панель, AI и автоматика не
вызывают Telegram или API тикетов напрямую, поэтому не обходят окно ответа и
всегда записывают исходящее сообщение в историю.

AI подписан на события хранилища и одинаково работает для обоих каналов.
Миграции только добавляются в конец `MIGRATIONS`: уже применённые миграции
нельзя изменять задним числом.

Подробная раскладка модулей и инварианты находятся в
[ARCHITECTURE.md](ARCHITECTURE.md).

## Ограничения

- Bot API не загружает старую личную переписку: панель начинает собирать её
  только после запуска.
- Ответ в тикет поддерживает только текст; входящие вложения при этом доступны.
- API ответа в тикет не идемпотентен. После сетевого обрыва нужно проверить
  историю перед повторной отправкой.
- К аккаунту Telegram можно подключить только одного бизнес-бота.
- Telegram помечает ответы флагом `via_business_connection`.
- Билет чтения WebSocket и вложений действует десять минут и временно виден в
  URL. Он не разрешает изменения, но access-логи следует считать чувствительными.
- В панели нет отдельных ролей: любой владелец `PANEL_TOKEN` является оператором.
