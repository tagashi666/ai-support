# ai-support

[![CI](https://github.com/tagashi666/ai-support/actions/workflows/ci.yml/badge.svg)](https://github.com/tagashi666/ai-support/actions/workflows/ci.yml)
[![License: MIT](https://img.shields.io/badge/License-MIT-blue.svg)](LICENSE)
[![Node.js 22+](https://img.shields.io/badge/Node.js-22%2B-43853d.svg)](package.json)

Самостоятельно размещаемая панель поддержки. Личные чаты аккаунта техподдержки
и тикеты внешней системы приходят в один инбокс, отвечать можно оттуда же, а AI
готовит ответы с опорой на базу знаний.

Личка подключается через **connected business bot** — официальный механизм
Telegram Business. Никакого MTProto, файла сессии и риска бана: бот получает
апдейты `business_message` и отвечает от имени аккаунта.

Структура проекта, инварианты и точки расширения — в **[ARCHITECTURE.md](ARCHITECTURE.md)**.
Что AI может и чего не может, чем закрыта панель — в **[SECURITY.md](SECURITY.md)**.

## Что умеет

- **Два канала в одном инбоксе** — личка аккаунта и тикеты бедолаги.
- **Ответ от имени аккаунта**, клиент не видит стороннего бота.
- **AI с базой знаний** — три режима: молчит, предлагает, отвечает сам.
- **Ворота автоответа** — чувствительные темы, низкая уверенность и недавняя
  работа человека автоматически возвращают диалог оператору.
- **Карточка клиента** из своего Support API и из бедолаги.
- **Окно 24 часов** как объект первого класса, а не сноска в документации.
- **Передача человеку** — AI предупреждает клиента, что вопрос у специалиста,
  и дальше молчит по существу, пока оператор не ответит.
- **Уведомления в Telegram** — по умолчанию каждое сообщение клиента и каждый
  ответ AI, плюс новое обращение, эскалация, агрессия, передача человеку и
  просрочка. С сутью, тоном, черновиком ответа и ссылкой на диалог.
  Подробность переключается в настройках: всё / только важное / минимум.
- **Шаблоны ответов, заметки, статистика**, включая долю принятых предложок AI.
- **Вложения** скачиваются к себе и показываются в панели.

## Установка

Пошаговая инструкция с nginx, каналами и диагностикой — в **[DEPLOY.md](DEPLOY.md)**.
Выбор модели и готовые конфиги провайдеров — в **[PROVIDERS.md](PROVIDERS.md)**.
Коротко:

```bash
git clone https://github.com/tagashi666/ai-support.git
cd ai-support
./install.sh          # создаст .env и сгенерирует токен панели
nano .env             # впиши BOT_TOKEN, остальное включишь позже
./install.sh          # соберёт, прогонит проверку и запустит
```

Без Docker:

```bash
cp .env.example .env && nano .env
npm install
npm run selfcheck     # что настроено, а что молча не работает
npm run dev
```

Панель: `http://127.0.0.1:8080`, токен спросит при первом входе.

## Подключение аккаунта

1. **@BotFather → Bot Settings → Business Mode → Enable.** Без этого подключение
   отвалится с `BOT_BUSINESS_MISSING`. `npm run selfcheck` проверяет этот флаг.
2. В аккаунте поддержки: **Настройки → Telegram для бизнеса → Чат-боты**, выбрать бота.
3. Права выдать только два: **отвечать на сообщения** и **отмечать прочитанным**.
   Управление профилем, подарками, звёздами и сторис боту не нужно.
4. В разделе «Чаты» начни с белого списка из пары своих аккаунтов, клиентов
   подключишь, когда убедишься, что всё работает.

Premium не требуется: подключённые боты доступны и без подписки. К одному
аккаунту подключается **только один** бизнес-бот — если там уже что-то висит,
старое отключится.

## Окно 24 часов

Telegram разрешает боту писать в личный чат, только если оттуда было входящее
за последние сутки. Это не наше ограничение и обойти его нельзя.

- `conversation.last_inbound_at` обновляется на каждом входящем;
- `Outbox` отказывает `WindowClosedError`, не доходя до Telegram;
- ворота AI возвращают `skip`, а не пытаются отправить;
- в панели поле ввода меняет цвет по мере истечения и блокируется, когда время вышло.

Проактивный follow-up через двое суток ботом невозможен — только руками.
На тикеты бедолаги окно не распространяется.

## Режимы AI

| `AI_MODE` | Поведение |
|---|---|
| `off` | AI не трогает диалоги вообще |
| `suggest` | пишет предложку, отправляет человек — **начинай с этого** |
| `auto` | отправляет сам, когда ворота пропускают |

Режим можно переопределить на конкретном диалоге. Диалог по умолчанию
наследует глобальный и **не может быть агрессивнее** его: при `AI_MODE=suggest`
переключение диалога в `auto` даст всё те же предложки.

Даже в `auto` ответ уходит человеку, если:

- модель поставила `needs_human` или уверенность ниже `AI_MIN_CONFIDENCE`;
- тема чувствительная — возвраты, двойные списания, обвинения, угрозы судом,
  прямая просьба позвать оператора;
- диалог эскалирован;
- человек отвечал в нём последние `AI_HUMAN_HOLD_MINUTES`;
- исчерпан лимит `AI_AUTO_PER_HOUR`.

Каждый черновик сохраняется в `ai_suggestion` со статусом. Доля `sent` и
`edited` против `rejected` — метрика того, готов ли AI к `auto`. Она видна
в разделе «графики».

## База знаний

Два источника, оба синхронизируются каждые 15 минут:

- `kb/*.md` — файлы в репозитории, первый заголовок становится названием;
- FAQ из админки бедолаги (`GET /pages/faq`) — правка там доезжает сама.

Поиск — FTS5 внутри SQLite, без эмбеддингов и внешних сервисов. Синхронизация
полностью заменяет документы источника, поэтому удаления тоже доезжают.

## База знаний из своей переписки

Три источника, у каждого своя область:

```bash
# закрытые тикеты бедолаги — основной архив
npm run kb:mine -- --archive --dry-run
npm run kb:mine -- --archive --limit 300

# личка: истории у Bot API нет, нужна выгрузка Telegram Desktop
npm run kb:mine -- --export ~/result.json            # покажет участников
npm run kb:mine -- --export ~/result.json --me user123456789

# то, что панель насобирала сама
npm run kb:mine                  # где база знаний подвела
npm run kb:mine -- --all         # все отвеченные диалоги
```

`--archive` ходит за тикетами в статусе `closed` напрямую в API бедолаги —
поллер их не забирает и в базе панели их нет. Личку через Bot API поднять
нельзя вовсе: он не отдаёт историю, поэтому только экспорт из Telegram Desktop
(Настройки → Экспорт данных → JSON).

Без источника берутся диалоги с **отклонёнными и правлеными предложками** —
места, где база не сработала, а правильный ответ человека лежит рядом.

Обращения сначала группируются по темам одним дешёвым запросом к модели, и
тема уезжает на синтез целиком: иначе полсотни тикетов «не подключается» дали
бы полсотни почти одинаковых статей. Лексическая группировка оставлена
запасным путём на случай отказа модели, но она заведомо грубее — люди
описывают одну проблему совершенно разными словами, и пересечение словаря
этого не ловит.

Тема «прочее» — благодарности, претензии без вопроса, единичные случаи —
до синтеза не доезжает: статей из неё всё равно не выйдет, а токены она тратит.

Запросы нарезаются **по токенам, а не по числу пар**: лимит провайдера
считается в токенах в минуту, и одна крупная тема целиком упирается в него.
Тема, которая не влезает в `AI_MINE_BUDGET_TOKENS`, режется на части без
потерь. Между запросами выдерживается `AI_MINE_PACE_MS`, иначе второй почти
наверняка получит 429.

`--dry-run` доходит до группировки, показывает крупнейшие темы, расход и
время прохода, но синтез не запускает.

Статьи пишутся в `kb/draft/` и **в ответы клиентам не идут**: сканер читает
только `kb/`, вложенные каталоги не трогает. Это не соглашение, а структурная
гарантия — сгенерированная AI база, которой кормится AI, отвечающий клиентам,
без ревью превращается в петлю, где однажды сказанная неточность становится
официальной версией.

```bash
mv kb/draft/statya.md kb/       # так статья становится рабочей
```

Переписка чистится **до** отправки в модель: ключи подписок, ссылки, uuid,
токены, карты, телефоны, ip, telegram id и юзернеймы заменяются заглушками.
Пары, где после чистки осталось что-то похожее на секрет, отбрасываются целиком.

## Архитектура

```
business_message ──┐                        ┌── business_connection_id
                   ├──→ Store ──→ Outbox ───┤
bedolaga poll ─────┘      │                 └── POST /tickets/{id}/reply
                          ↓
                   панель (WS) + AI + SLA
```

`Outbox` — единственный выход наружу. Панель, AI и автоматика ходят только
через него; прямые вызовы `bot.api.send*` из логики запрещены, иначе появятся
пути отправки в обход окна 24 часов и мимо истории диалога.

AI подписан на события хранилища, а не на конкретный канал, поэтому одинаково
реагирует и на личку, и на тикеты.

Раскладка по слоям и правила, которые нельзя нарушать, описаны в
[ARCHITECTURE.md](ARCHITECTURE.md).

Миграции только дописываются в конец массива `MIGRATIONS`. Править применённую
миграцию нельзя: база уже на этой версии и повторно её не проиграет.

## Проверка

```bash
npm test          # полный набор проверок, без сети и настоящих токенов
npm run selfcheck # что реально настроено на этом сервере
```

| Набор | Что закрывает |
|---|---|
| `smoke.ts` | приём лички, дедуп, окно, отказы outbox |
| `webtest.ts` | API панели, авторизация, WebSocket |
| `aitest.ts` | ворота AI, разбор ответа модели, FTS-поиск, поллер бедолаги |
| `minetest.ts` | выгрузка Telegram, архив тикетов, кластеризация тем |
| `notifytest.ts` | доставка уведомлений, троттлинг, поведение при отказе |
| `uitest.ts` | структура панели: сетка, скрытие экранов, ссылки на id |
| регрессии в `aitest.ts` | метрика первого ответа, бэкфилл, пороги SLA, мёртвые вложения |

API бедолаги в тестах поднимается заглушкой на localhost, модель не вызывается.

## Деплой

```bash
docker compose up -d --build
```

Порт публикуется на `127.0.0.1` намеренно: Docker пишет правила в обход UFW,
и `ports: "8080:8080"` открыл бы панель всему интернету. Наружу пускает
системный nginx — конфиг с настройками WebSocket в `deploy/ai-support.conf`.

## Если клиент не находится в Remnawave

```bash
docker compose run --rm ai-support node dist/cli/rwprobe.js 123456789 example_user
```

Печатает по шагам: что ответили точечные ручки, какой размер страницы приняла
панель, сколько записей попало в индекс, какой способ сработал и какие записи
похожи. То же самое доступно в панели кнопкой «Почему не нашёлся».

Связка ищется пятью способами, потому что единого поля нет: точное `telegramId`,
ник вида `user_{telegram_id}_*` (так их заводит бедолага), telegram id в поле
«Описание», `@ник` в описании, short uuid из ссылки на подписку.

Параметр `search` у панели ненадёжен — на живой инсталляции он игнорируется и
возвращает всю базу с начала. Поэтому список выгребается страницами в
собственный индекс, а совпадение проверяется на нашей стороне: иначе оператору
показался бы первый попавшийся человек вместо нужного.

## Если что-то не работает

Панель показывает ошибку сервера на каждое действие — «Опубликовать»,
«Сохранить», «Отправить». Если появилось сообщение про права доступа:

```bash
chown -R 1000:1000 kb data && docker compose restart
```

Каталоги создаёт root, а контейнер работает под uid 1000. `install.sh`
выставляет владельца сам, `npm run selfcheck` проверяет запись, и приложение
пишет об этом в лог при старте.

## Известные ограничения

- **История не подтянется.** Bot API не умеет читать переписку задним числом,
  панель стартует с чистого листа. Старые диалоги остаются в самом Telegram.
- **Ответ в тикет — только текст.** `POST /tickets/{id}/reply` принимает
  `message_text`, картинку в тикет отправить нельзя. Входящие вложения качаются.
- **`POST /reply` не идемпотентен**: сообщение коммитится до ответа эндпоинта,
  поэтому ретраи на нём отключены намеренно. При обрыве связи ответ мог уйти —
  проверь тикет перед повторной отправкой.
- **Один бизнес-бот на аккаунт** — ограничение Telegram.
- **Ответы от бизнес-бота помечены** флагом `via_business_connection`.
  Полной невидимости бота не бывает.
- **Билет на чтение временно виден в URL** WebSocket и вложений. Он действует
  десять минут и не даёт изменять данные, но access-логи всё равно следует
  считать чувствительными.
