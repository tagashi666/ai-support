# Архитектура ai-support

Документ для того, кто продолжит работу — человека или модели. Он объясняет
не что где лежит (это видно из дерева), а **почему устроено именно так** и
какие правила нельзя нарушать, не сломав продукт.

## Что это

Одна панель для двух источников обращений: личные чаты аккаунта поддержки в
Telegram и тикеты бота бедолаги. Сверху — AI, который предлагает ответы или
отвечает сам, и уведомления оператору в Telegram.

## Слои

```
src/
  config.ts          Чтение .env, валидация, версия сборки
  index.ts           Сборка всего вместе: что от чего зависит

  core/              Домен. Не знает ни про Telegram, ни про AI
    db.ts            SQLite, миграции по user_version
    store.ts         Диалоги, сообщения, база знаний, статистика
    outbox.ts        Единственный выход наружу
    settings.ts      Настройки, правимые из панели
    notify.ts        Уведомления оператору, определение тона
    sla.ts           Кто ждёт ответа слишком долго
    media.ts         Скачивание вложений, расшифровка голосовых
    templates.ts     Заготовки ответов

  channels/          Источники обращений. Каждый умеет принимать и отвечать
    tgdm.ts          Личка через business-подключение Telegram
    bedolaga.ts      Тикеты: клиент API, поллер, отправитель

  ai/                Всё, что связано с моделью
    provider.ts      Вызов OpenAI-совместимого API, ротация ключей,
                     ретраи, чистка размышлений, расшифровка
    responder.ts     Сборка контекста, черновик, решение
    gate.ts          Когда автоответ НЕ уходит
    kb.ts            Синхронизация базы знаний
    cluster.ts       Группировка обращений по темам
    scrub.ts         Чистка переписки перед отправкой наружу
    mining.ts        Сбор статей из реальных диалогов
    sublink.ts       Ключи подписки в сообщениях клиента

  integrations/      Внешние системы только на чтение
    customers.ts     Карточка клиента из всех источников
    remnawave.ts     Подписка, устройства, поиск клиента
    tgexport.ts      Разбор выгрузки Telegram Desktop

  panel/             Веб-интерфейс
    server.ts        HTTP API и WebSocket
    kbfiles.ts       Файлы базы знаний, защита пути

  cli/               Точки входа для консоли
    selfcheck.ts     Предполётная проверка
    kbmine.ts        Сбор базы знаний
    rwprobe.ts       Разбор связки с Remnawave

public/index.html    Панель целиком: разметка, стили, логика
MANIFEST             Список файлов релиза. Установщик удаляет по нему
                     всё, чего в новой версии больше нет
kb/*.md              База знаний. Правится в панели или руками
scripts/*.ts         Тесты. Сеть не нужна, токены не нужны
```

Зависимости идут в одну сторону: `channels` и `ai` знают про `core`, `core`
не знает про них. Панель знает про всё, её никто не знает.

## Правила, которые нельзя нарушать

**Наружу пишет только Outbox.** Панель, AI и автоматика вызывают
`outbox.send()`. Прямые `bot.api.sendMessage` в логике запрещены: там живёт
проверка окна ответа и запись в историю. Единственные исключения —
отправитель канала внутри `channels/tgdm.ts` и уведомления оператору.

**Окно 24 часов — не сноска, а состояние.** Telegram разрешает боту писать в
личный чат, только если оттуда было входящее за последние сутки. Проверка
живёт в Outbox, а не в панели: иначе любой новый вызывающий её обойдёт.

**Миграции только дописываются.** Массив `MIGRATIONS` в `core/db.ts`, версия
в `PRAGMA user_version`. Править применённую миграцию нельзя — база уже на
этой версии и повторно её не проиграет.

**Черновики базы знаний лежат вне `kb/`.** Сканер читает только `kb/`,
черновики — в `data/kb-draft/`. Это структурная гарантия: сгенерированная
моделью статья не может попасть в ответы клиентам, пока человек её не
перенёс. Без неё AI начинает учиться на собственных неточностях.

**Опора на базу знаний считается по названным выдержкам.** Модель обязана
вернуть номера статей, на которых построила ответ. Совпадения по словам
недостаточно: вопрос про сервер цепляет статью про скорость, а ответа в ней
нет — так в прод уехал выдуманный ответ про отсутствие сбоев.

**Модель не вызывает действий.** В запросе к провайдеру нет `tools`, в слое
`ai/` нет обращений к Remnawave. Разрушающие действия живут только в
`panel/server.ts` и требуют подтверждения оператора. Подробнее — SECURITY.md.

**Переписка чистится перед отправкой в модель.** `ai/scrub.ts` вырезает
ключи, ссылки, карты, телефоны, telegram id. При майнинге наружу уходит
пачка чужих диалогов — это не то же самое, что один ответ клиенту.

**Разрушающие действия делает человек.** Сброс устройств, удаление
устройства, перевыпуск подписки — только оператор из панели с
подтверждением. AI их не вызывает: клиент почувствует это немедленно.

**Обещание клиенту и уведомление оператору атомарны.** Если AI написал
«передал специалисту», уведомление обязано уйти. Событие `handoff` не
подавляется троттлингом, а при недоставке в диалог падает заметка.

## Как всё связано во времени

```
Входящее (Telegram или поллинг тикетов)
      ↓
store.recordInbound()  ← вложение регистрируется ДО события,
      ↓                  иначе панель получит пустой пузырь
событие 'message'
      ├→ панель (WebSocket)
      ├→ уведомление оператору
      └→ responder.schedule()  ← пауза 12 с: клиент дописывает мысль
              ↓
         handleInbound()
              ├ тон агрессивный → эскалация + уведомление
              ├ диалог у человека → только напоминание «ожидайте»
              ├ обращения нет → молчим
              ↓
         модель → черновик
              ↓
         gate.decide()
              ├ auto    → outbox.send()
              └ suggest → предложка + handoff + уведомление
```

## Отзывчивость панели

Открытие диалога не ходит во внешние системы. `GET /api/conversations/:id`
отдаёт только локальные данные и помечает карточку клиента как несвежую;
панель рисует шапку из уже загруженного списка, показывает переписку, а
карточку и подписку догружает фоном. Раньше этот запрос ждал бедолагу и
Remnawave — вплоть до пересборки индекса на полторы тысячи записей, и
переключение занимало около секунды.

Правила, которые держат плавность:

- в пути переключения диалога нет `await` на сеть, кроме самой переписки;
- список перерисовывается только при изменении состава, выделение
  переключается атрибутом;
- анимации трогают только `transform` и `opacity` — всё остальное
  заставляет браузер пересчитывать раскладку;
- размытие фона живёт только на мелких всплывающих слоях: на полноэкранных
  поверхностях оно пересчитывается каждый кадр.

Эти правила проверяются в `scripts/uitest.ts`, а не держатся на памяти.

## Точки расширения

**Новый канал.** Реализовать `ChannelSender` и вызывать
`store.recordInbound()` на входящие. AI, уведомления и SLA подхватят его
сами — они подписаны на события хранилища, а не на конкретный канал.

**Другая модель.** `AI_BASE_URL` и `AI_MODEL` в `.env`. Провайдер говорит на
OpenAI-совместимом протоколе, ничего больше не требуется. В `AI_API_KEY`
можно перечислить несколько ключей через запятую: на 429 клиент меняет ключ,
а не ждёт окна, отвергнутый 401 помечает мёртвым и больше не трогает.

**Размышления модели.** Reasoning-модели выдают ход мысли в тегах `<think>`.
Он вырезается в `provider.ts` до любого разбора — не только ради чистоты
ответа: скобка внутри размышления уводила извлечение JSON, и ответ терялся
целиком. Поэтому JSON ищется по балансу скобок, а не от первой до последней.

**Новое условие для автоответа.** Только в `ai/gate.ts`. Логика решения
намеренно собрана в одном файле и покрыта тестами покейсово.

**Новая настройка из панели.** Добавить поле в `Runtime` и валидатор в
`FIELDS` (`core/settings.ts`), затем строку в `FIELDS` панели. Ключи и
токены туда не выносятся: панель не должна быть способом увести доступ.

## Тесты

```bash
npm test          # без сети и без настоящих токенов
npm run selfcheck # что реально настроено на этом сервере
```

| Набор | Что закрывает |
|---|---|
| `uitest.ts` | структура панели: сетка, скрытие экранов, ссылки на id |
| `smoke.ts` | приём лички, вложения, дедуп, окно, отказы outbox |
| `webtest.ts` | API, авторизация, WebSocket, разбор тела запроса |
| `aitest.ts` | ворота, тон, склейка, передача человеку, связка с панелью |
| `minetest.ts` | выгрузка Telegram, архив тикетов, группировка тем |
| `notifytest.ts` | доставка уведомлений, уровни, троттлинг, отказы |

Внешние API поднимаются заглушками на localhost. Модель не вызывается.
Каждый найденный в проде баг закреплён отдельной проверкой — список в
истории коммитов и в комментариях к тестам.

## Что осознанно не сделано

- **Истории переписки нет.** Bot API не отдаёт прошлые сообщения. Панель
  стартует с чистого листа, архив живёт в Telegram и в бедолаге.
- **Ответ в тикет только текстом** — ограничение API бедолаги.
- **Один бизнес-бот на аккаунт** — ограничение Telegram.
- **Нет очередей и воркеров.** Нагрузка — десятки обращений в день;
  SQLite и таймеры в процессе честнее, чем Redis ради галочки.
